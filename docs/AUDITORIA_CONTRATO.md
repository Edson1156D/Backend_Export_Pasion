# Auditoria de contrato backend / frontend

Fecha: 2026-09-29  
Alcance: lectura de `app/api/v1/`, `docs/GUIA_BACKEND.md` y el repositorio frontend.

## Resumen

El backend define 28 endpoints bajo `/api/v1`. El frontend tiene mocks equivalentes para casi todos, pero **ningun `*.service.ts` llama actualmente al backend**: las operaciones usan `localStorage` mediante `createLocalStore`. Axios solo esta preparado en `src/lib/axios.ts`; no hay integracion de JWT ni reemplazo de mocks.

Los estados de esta tabla evalúan el contrato y la posibilidad de conectar el frontend actual, no solo si existe un mock con una funcion de nombre parecido.

## Reglas transversales

- **Prefijo y envoltorio:** las rutas backend estan bajo `/api/v1` y devuelven objetos/listas directos, sin `{data: ...}`.
- **CamelCase:** los response models backend usan aliases camelCase. Los servicios frontend mock usan las mismas formas principales, con excepciones de payload de ventas, responsable y campos derivados.
- **Numeros:** el backend convierte `Decimal` a `float`; los modelos frontend los tipan como `number`. Esto es compatible cuando se conecte HTTP.
- **IDs:** el backend serializa IDs de usuario como `string`; el frontend usa strings/UUIDs en mocks. Los IDs de productos y entidades se usan como numeros en los schemas de formulario.
- **Fechas:** el backend usa datetimes UTC, pero la serializacion puede quedar como `+00:00`; la guia exige explicitamente ISO con sufijo `Z`. Debe verificarse al conectar el frontend.
- **Errores:** los handlers backend producen `{"detail": "texto"}` para HTTP, negocio y 422. Axios frontend esta preparado para leer errores, pero los servicios mock no atraviesan `error.response.data.detail`. Ademas, algunas validaciones internas que lanzan `ValueError` podrian terminar como 500 en vez de 400 si llegan por una ruta no cubierta por el servicio.
- **Permisos:** el backend aplica la matriz de la guia. El frontend oculta pantallas por rol, pero sus mocks no pueden demostrar ni aplicar los 401/403 reales. La diferencia mas visible es ventas propias: la pantalla existe, pero hoy no filtra mediante `/ventas/mias`.
- **Negocio:** FIFO, `round2` half-up, folios de ventas/comercio exterior, responsable desde token, snapshots y atomicidad estan implementados en backend. Los mocks no reproducen completamente esas garantias.
- **Consumidores HTTP ausentes:** ningun `*.service.ts` del frontend llama actualmente a estos 28 endpoints. Los archivos listados son consumidores mock o equivalentes de UI. No hay consumidor frontend equivalente para `/auth/me` ni `/dashboard/resumen`.

## Top prioridades

1. **Autenticacion real:** conectar `auth.service.ts` y `AuthProvider` a `POST /auth/login`, persistir `accessToken` y configurar Bearer en Axios; de lo contrario todas las rutas protegidas fallaran con 401.
2. **Registro de ventas:** adaptar el payload al contrato minimo del backend y manejar sus reglas de stock, efectivo, FIFO y atomicidad; el POS actual envia snapshots/precios del mock y no usa token.
3. **Ventas propias:** implementar `GET /ventas/mias` en el servicio/hook del vendedor; hoy la pantalla puede mostrar ventas de todos los usuarios cuando se sustituya el mock sin este filtro.
4. **Dashboard:** reemplazar cifras hardcodeadas y el calculo mock por `GET /dashboard/resumen?periodo=...`; hoy el endpoint no tiene consumidor.
5. **Errores y validaciones de formularios:** hacer que el interceptor muestre `error.response.data.detail` y alinear motivos de merma, errores de stock, duplicados y permisos; hoy los mocks no ejercitan esos contratos.
